------------------------------------------------------------

Instead, a wholly separate, self-contained PostgreSQL cluster was
created using the same PostgreSQL 18 binaries already on disk
(`initdb.exe`), entirely isolated from the existing installation:

  the existing installation's data directory).

  created via `initdb` -- not a guess or bypass of any existing
  credential.
- Trust authentication local to this one throwaway cluster only.
- Listening ONLY on `127.0.0.1:5433` -- a different port from the
  existing service's `5432`, so the two never touched or conflicted with
  each other at any point.

Steps performed:
1. Created the isolated cluster and started it on port 5433.
2. Created a fresh database, `alphaone_deploy_test`, inside that cluster.
3. Set `DATABASE_URL` / `DATABASE_URL_SYNC` for this cluster as
   process-local environment variables for the one command that needed
   them -- never written to the real `.env` file.
4. Ran `alembic upgrade head` -- **all 6 revisions applied with zero
   errors**: 001 (initial schema), 002 (Phase 2 derivatives/candle
   quality/backtest tracking), 003 (Phase 4 manual trading), 004 (Phase 5
   CoinDCX live sync fields), 005 (production-deployment schema-drift
   fix).

   - All 21 expected tables present (`accounts`, `trades`, `signals`,
     `sync_events`, `notification_logs`, `candles`, `alembic_version`,
     etc.).
   - Both cross-dialect partial unique indexes exist AND are genuinely
     partial on real Postgres (confirmed via `pg_get_indexdef`):
     `CREATE UNIQUE INDEX ix_trades_exchange_trade_id ON trades USING
     btree (exchange_trade_id) WHERE (exchange_trade_id IS NOT NULL)`,
     and the equivalent for `trade_executions.exchange_transaction_id`.
   - `alembic_version` correctly stamped at `005` (head).
6. Ran a basic APPLICATION-level DB connectivity test -- not just raw
   `psql`, but the app's own `create_async_engine`/`async_sessionmaker`
   and real ORM models (`Account`) against this Postgres instance:
   - Raw `SELECT 1` through the app's own async engine: succeeded.
   - Inserted a real `Account` row and read it back: succeeded. The
     cross-dialect `GUID` column correctly round-tripped as a native
     Python `uuid.UUID` (Postgres's native `UUID` type, as designed),
     and the naive-UTC `created_at` timestamp round-tripped with
     `tzinfo=None`, consistent with this codebase's UTC convention
     everywhere else (see the prior deployment-readiness report's
     timezone section).
7. The user's existing PostgreSQL installation/service/database was never
   connected to, queried, or modified at any point in this process --

8. Cleanup: the throwaway cluster was stopped (`pg_ctl stop -m fast`) and

WHAT WAS BUILT
------------------------------------------------------------

services/market_data/live_state.py now owns a `_StartupRetrySupervisor`:
a single background task that retries ONLY the live market-data
WebSocket's INITIAL connect() with exponential backoff
(2s/4s/8s/16s/30s, holding at 30s once the table is exhausted). The
moment that first connect succeeds, the supervisor's job is done --
every subsequent drop/reconnect is handled entirely by
CoinDCXMarketDataWebSocket's own existing, unmodified python-socketio
reconnection (services/market_data/coindcx_ws.py was not touched).
apps/api/main.py's lifespan was NOT modified -- it still calls
`asyncio.create_task(start_market_data_ws())` / `stop_market_data_ws()`
exactly as before; both functions kept their existing signatures and now
delegate to the supervisor internally.

1. INITIAL CONNECTION RETRY -- PASS

A failed first attempt is now retried automatically instead of leaving

3. SHUTDOWN HANDLING -- PASS
------------------------------------------------------------

`_StartupRetrySupervisor.stop()` sets a stop event AND cancels the retry
task directly, then awaits it to completion -- verified the task is
fully gone (not just marked done) and issues no further connection
attempts after stop() returns, even mid-backoff. `stop_market_data_ws()`
calls this before disconnecting market_ws itself, so FastAPI shutdown
cleanly tears down a still-retrying startup attempt.

------------------------------------------------------------
4. NO DUPLICATE RETRY LOOPS -- PASS
------------------------------------------------------------

Calling `start()` while already running is a no-op (logged, not silently
ignored) -- verified the second call never creates a second task; the
original task object is unchanged. Only a successful connect() ever
reaches CoinDCXMarketDataWebSocket._on_connect (where subscriptions
happen), and a failed retry attempt never reaches it at all -- so retries
can structurally never cause a duplicate subscription either.

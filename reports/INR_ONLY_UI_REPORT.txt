2. INR FORMATTER IMPLEMENTATION
------------------------------------------------------------

Two formatters, one per stack, both centralizing all currency display:

- Frontend: apps/web/lib/currency.ts -- formatINR(value, {showSign}) using
  Intl.NumberFormat('en-IN', {style:'currency', currency:'INR'}) for
  correct native Indian digit grouping (lakhs/crores). Returns "N/A" for
  null/undefined/NaN, never fabricates a number. showSign prefixes "+" for
  positive P&L values (zero never gets a sign).
- Backend/Telegram: services/common/currency.py -- format_inr(value,
  show_sign) implements the same Indian-grouping algorithm natively in
  Python (no formatting library dependency) for Telegram message text.

Both were unit-verified against the spec's own examples: ₹1,600.00,
₹1,00,000.00 (1 lakh), ₹10,00,000.00 (10 lakh), ₹1,23,45,678.90 (1.23 crore).

3. INR CONVERSION IMPLEMENTATION
------------------------------------------------------------

services/exchange/fx.py: get_usdt_inr_rate() fetches CoinDCX's real public
spot ticker (https://public.coindcx.com/exchange/ticker), reads the
"USDTINR" market's last_price as the conversion rate. This is a real,
directly-tradeable CoinDCX market -- a genuine, verifiable data source,
not a fabricated multiplier.

Deviation from the spec's suggested architecture, done deliberately and
disclosed rather than silently: the spec's diagram included a
"USDT/USD reference" hop before INR. That hop was dropped -- USDT is
already a USD-pegged stablecoin and there is no real, documented USD
reference source to insert there; adding one would mean fabricating a
number to satisfy the diagram's shape rather than improving accuracy.
CoinDCX's own USDT/INR spot market is used directly as the single,
verifiable conversion source.

Every converted value carries a full envelope: conversion_rate,
conversion_timestamp (when CoinDCX reported that price),
conversion_source ("CoinDCX USDT/INR spot ticker"), conversion_status
(LIVE / STALE after 5 minutes / UNAVAILABLE if the ticker call fails).
convert_usdt_to_inr() returns None -- never a guessed number -- if either
the source amount or the rate is missing; the frontend renders "INR
conversion unavailable" / "N/A" in that case, never a fake ₹ figure.
Verified live: real rate fetched during testing was 99.43-99.97 INR per
USDT (CoinDCX's real current market rate).

------------------------------------------------------------
4. DATA MODEL / "NO DOUBLE CONVERSION" HANDLING
------------------------------------------------------------

Per-value currency provenance was determined explicitly rather than
guessed, and is documented in docs/known_limitations.md:

- CoinDCX account balance/margin/positions: already native INR (the real
  account is INR-margined, per Phase 5's DEFAULT_MARGIN_CURRENCY="INR"
  decision) -- displayed via formatINR with NO conversion step.
- Signal entry/SL/TP and dashboard btc_price: USDT-denominated (Binance-
  sourced signal engine, unchanged since Phase 1-3) -- converted via
  fx.py before display.
- Manual trade-journal entries: assumed INR (user manually trades their
  INR-margined CoinDCX account) -- no conversion step.
- Chart candles: USDT-denominated (same Binance source) -- converted,
  using one current rate applied uniformly across the series (no
  documented historical USDT/INR rate history exists to do this per-bar
  historically-accurately; disclosed in the chart's subtitle, not hidden).

Raw values are preserved everywhere a conversion happens (e.g. dashboard
exposes both btc_price_usdt and btc_price_inr) so nothing is destroyed
internally, per spec section 13.

Tests covering all of this: test_fx_conversion.py (rate fetch success/
failure/staleness/caching, conversion math, never-fabricate-on-missing-
input) and test_format_inr.py (Indian grouping at all magnitudes, sign
handling, None handling).

9. REMAINING USD/USDT OCCURRENCES -- WHY THEY ARE LEGITIMATE
------------------------------------------------------------

Grepped the entire frontend source tree (excluding node_modules/.next
build output) for literal "$" and "USD": every remaining match is one of:
(a) JavaScript template-literal syntax (${variable}), not a currency
    symbol -- confirmed by manual inspection of every match, zero are
    rendered to the user as a dollar sign.
(b) The literal string "BTC/USDT" / "BTC/USDT PERPETUAL" -- the actual
    CoinDCX trading-pair/instrument identity, which the spec explicitly
    says must be preserved (section 15).
No bare "USD" (as a currency label) exists anywhere in the frontend.
Backend: grepped apps/api and services/telegram for literal "$" currency
formatting -- zero remain (all converted to format_inr()).
